### 4.3 Recommended staged ownership contract and resolution

**RECOMMENDATION, no execution:** (1) prior to activation, bind read-only accepted identity to a specific financial generation and leave legacy allocation authoritative; (2) under coordinated writer exclusion, capture/validate accepted IDs, reviews, aliases/provider mappings and issued-ID/high-water evidence, including any retained retired identities; (3) activate one StockCore allocator and route or disable all legacy creating/mapping/eligibility mutation paths; (4) financial generations retain their owner but consume a versioned accepted identity projection, and publication must reject a stale candidate that could restore a competing identity snapshot; (5) rollback/restore must preserve the same single-owner and issued-ID constraints. This contract makes future source ingestion independent of financial scoring while preserving accepted IDs. It requires no financial-engine migration or new specialized database. Actual bridge, publication compatibility and operational writer-exclusion verification remain **Q01 OPEN — DETAIL DESIGN**, blocking shared-allocation activation. **Source evidence question resolved; handoff not implemented/accepted.** Confidence high for paths above, bounded for external writer completeness. ### 6.3 Functioning, ineffective and unresolved behaviors

The separate market-regime source defaults to two consecutive CRASH candidates and serializes the state as CRASH_ALERT (`regime/production.py:9–18,82–108`). Its SP500/NDX combination is consensus or SIDEWAYS on disagreement; this remains a required standalone V1 context capability, not an input gate discovered in either policy.

**Shared history defect, not V3-only:** the [SQLite history port](../../../swingmaster/swingmaster/infra/sqlite/state_history_port_sqlite.py#L32) expects `reason_codes, signal_keys, churn_guard_hits` in one state table, filters date<=T and catches all query errors as `[]`. The [shipped state schema](../../../swingmaster/swingmaster/infra/sqlite/migrations/001_init.sql#L11) and [state writer](../../../swingmaster/swingmaster/infra/sqlite/repos/rc_state_repo.py#L94) use reasons_json; [signal writer](../../../swingmaster/swingmaster/infra/sqlite/repos/rc_state_repo.py#L172) stores signal_keys_json in rc_signal_daily. Inspected migrations do not supply the expected history projection. Thus enabling the shipped adapter against that shipped schema is insufficient. Actual customized live schema was not queried; no assertion every existing database has exactly that shape is made.

When history/context is absent, some helper behavior falls back to previous state/age/current signals, not complete inactivity: [_should_reset_to_neutral](../../../swingmaster/swingmaster/core/policy/rule_v1/policy.py#L349) has age/quiet/status fallback, [_edge_gone_decision](../../../swingmaster/swingmaster/core/policy/rule_v1/policy.py#L392) uses age when no history, and entry freshness has a permissive no-history branch. Recent-entry churn detection requires delivered history and is ineffective in traced daily/range wiring. A port returning empty history is also observably different from no port in some entry branches. This requires distinct absent/incomplete/error states, not treating all empty values alike.

V3 additions **can function through current signals/previous attrs** despite missing recent history: profiles, MA20/HL gates, phase/gate/quality metadata and shared invalidation. Their genuine effect must be assessed at final guarded output. A V3 gate overriding a delegated DOWNTREND_EARLY/LATE→STABILIZING proposal to ENTRY_WINDOW is rejected by the unchanged graph; from sufficiently aged STABILIZING it may be allowed. Insufficient min-age similarly blocks it. No blanket conclusion that V3 gates are useless follows.

The [V3 provider](../../../swingmaster/swingmaster/app_api/providers/osakedata_signal_provider_v3.py#L195) also produces STRUCTURE_BREAKOUT_UP_CONFIRMED from old Dow BOS_UP. A targeted read/search of the delegated V1/V2/V3 policy modules found no direct predicate consuming that new key; this is an emitted fact, not evidence of an additional implemented breakout transition. Its presence can still affect generic quiet-signal handling. V2Impl's optional ruleset argument is also not forwarded to its constructed V1Impl (`rule_v2/policy.py:26–31`), so that parameter is not an effective ruleset override in the traced chain.

**Potential correctness/detail gap:** [V3 override](../../../swingmaster/swingmaster/core/policy/rule_v3/policy.py#L158) reuses delegated decision age and reasons after changing next_state. If delegated state stayed STABILIZING with age incremented, an allowed override to ENTRY_WINDOW can retain that increment rather than a fresh state's age0; underlying reason codes may still describe the delegated proposal. This is a static consequence for the stated branch, not measured deployed incidence. Q16 must settle/test proposal/final age/reason invariants while preserving approved minimum-age/graph rules; do not silently declare the current inconsistency an approved investment rule or redesign the policy to hide it.
